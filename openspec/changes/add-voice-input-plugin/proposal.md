## Why

The dashboard has no voice input capability. Users must type every prompt, which is slow on mobile and inconvenient in hands-free scenarios. The plugin system already supports UI extension through slots, but the `CommandInput` component (the textarea + Send/Stop buttons) has no extension point — plugins cannot add buttons or controls to the input area.

Two gaps must be closed:
1. A new `command-input-action` slot in the frozen slot taxonomy, rendered inline in the `CommandInput` button row
2. A voice-input plugin that uses this slot to add a push-to-talk / toggle mic button

For speech-to-text, parakeet.js provides browser-native ASR via ONNX Runtime Web (WebGPU/WASM). The same NVIDIA Parakeet ONNX models can also run server-side via `onnxruntime-node`, giving a consistent model family for both client and server transcription paths — important for mobile where the 600MB model is impractical in-browser.

## What Changes

- **NEW**: `command-input-action` slot in the slot taxonomy (`SlotId`, `SessionScopedSlot`, `SLOT_DEFINITIONS`). Multiplicity: many, payload tier: react-only, session-scoped.
- **NEW**: `SlotProps<"command-input-action">` with `{ session, pluginContext, onInsertText }`. The `onInsertText` callback lets plugin components insert text into the CommandInput textarea.
- **NEW**: `CommandInputActionSlot` consumer component in `dashboard-plugin-runtime/slot-consumers.tsx`, following the same pattern as `SessionCardActionBarSlot`.
- **MODIFIED**: `CommandInput.tsx` renders `<CommandInputActionSlot>` in the button row (before Send/Stop) when a `session` prop is provided. Passes `onInsertText` that appends to the controlled draft.
- **MODIFIED**: `App.tsx` passes `session={selectedSession}` to `<CommandInput>`.
- **NEW**: `packages/voice-input-plugin/` — a dashboard plugin with:
  - `MicButton` component (for `command-input-action` slot): push-to-talk and toggle recording modes, microphone permission handling, recording pulse animation, live text overlay
  - `VoiceInputSettings` component (for `settings-section` slot, tab: general): mode, transcription engine, server engine, language, VAD threshold, model paths
  - Server entry (`src/server/index.ts`): `voice_input_audio` browser handler for server-side audio chunks + `/api/voice-input/health` route (stub)
  - Config schema (`configSchema.json`): JSON Schema 7 with defaults for all settings
- **NEW**: 17 tests (10 MicButton, 7 VoiceInputSettings), all passing with jsdom + `PluginContextProvider` + `CurrentPluginLayer`.

### Transcription architecture

| Mode | Runtime | Library | Where |
|------|---------|---------|-------|
| Client | WebGPU/WASM | `parakeet.js` (onnxruntime-web) | Browser |
| Server | CPU (or CUDA) | `onnxruntime-node` (direct) | Dashboard server |

Both use the same Parakeet TDT 0.6B v3 ONNX model files from HuggingFace (`ysdede/parakeet-tdt-0.6b-v3-onnx`). Server mode also supports OpenAI Whisper API as a fallback.

### What's currently stubbed (needs real implementation)

| Server audio transport | Protocol defined, stubs in client + server | Base64-encode audio chunks, send via `voice_input_audio` WS messages |
| Server transcription | Placeholder echo | Integrate onnxruntime-node + Parakeet ONNX models |
| Model download | — | Download ONNX model files from HuggingFace CDN on first use |

## Capabilities

### New Capabilities

- `voice-input-plugin`: a push-to-talk / toggle mic button in the command input bar with configurable recording mode, transcription engine, and language.
- `command-input-action-slot`: a new plugin slot that renders action buttons inline in the CommandInput button row.

### Modified Capabilities

None. The existing plugin slots continue to work unchanged. The frozen slot taxonomy gains one new entry.
